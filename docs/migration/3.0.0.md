# Migrating to App Toolkit 3.0.0: navigation

3.0.0 replaces the Toolkit's navigation with a one-activity shell. The old navigation is removed,
not deprecated: code that used it no longer compiles. This guide maps each removed API to its
replacement and walks through moving an app over. `:sample:app` is a complete example of the result.

The module READMEs hold the details:

- [`:library:navigation`](../../library/navigation/README.md): the graph, navigator, scenes,
  transitions, predictive back and the Toolkit's keys.
- [`:library:shell`](../../library/shell/README.md): `ShellHost` and the chrome.
- [`:library:core:ui`](../../library/core/ui/README.md#page-frame): the page frame.
- [`:library:apptoolkit`](../../library/apptoolkit/README.md#navigation): `toolkitGraph { }` and
  the Toolkit's pages.
- [`:library:feature:developer`](../../library/feature/developer/README.md): the developer options.

## What changes for an app

Before, an app built its own main screen: a `NavDisplay` over a `NavigationState`, entry builders
from each feature and `appToolkitNavigationEntryBuilders`, a `BottomNavigationBar` or
`LeftNavigationRail`, a `NavigationDrawerSheet` filled by a `NavigationRepository`, and a
`MainTopAppBar`. Toolkit screens such as Settings, Help and Support opened as activities.

Now an app declares a graph once, and `ShellHost` draws everything: the app bar, the navigation bar,
rail or drawers for the window size, the overflow menu, the transitions and the back gesture.
Screens move with `LocalShellNavigator.current.navigate(key)`.

## Step by step

### 1. Make your keys serializable

Every key becomes a Navigation 3 `NavKey` annotated with `@Serializable`. Apply the Kotlin
serialization plugin in each module that declares keys.

```kotlin
// Before
@Parcelize
data object HomeRoute : StableNavKey {
    override val destinationType get() = NavigationDestinationType.TopLevel
}

// After
@Serializable
data object HomeRoute : NavKey
```

`destinationType` is gone. Whether a key is a tab, a child pushed on a tab, or a page over the
shell is declared in the graph instead.

### 2. Declare the graph

Replace entry builders, bottom bar items and drawer items with one graph. `toolkitGraph { }` adds
the Toolkit's pages; use `shellGraph { }` from `:library:navigation` for an app that does not use
`:library:apptoolkit`.

```kotlin
val graph = toolkitGraph(appTitle = R.string.app_name, appIcon = ToolkitIcon.Resource(R.drawable.app_logo)) {
    tab(HomeRoute, R.string.home, ToolkitIcon.AnimatedVector(R.drawable.anim_home)) {
        HomeScreen(paddingValues = contentPadding())
    }
    tab(
        key = LibraryRoute,
        label = R.string.library,
        icon = ToolkitIcon.Vector(Icons.Outlined.VideoLibrary),
        fab = { AddButton() },
    ) { LibraryScreen() }
    child<ItemRoute>(title = { it.name }) { item -> ItemScreen(item) }
    page<AboutAppRoute>(title = { stringResource(R.string.about) }) { AboutAppScreen() }

    drawer {
        settings()
        link(HelpRoute, R.string.help_and_feedback, ToolkitIcon.Vector(Icons.AutoMirrored.Outlined.HelpOutline))
        action(R.string.share, ToolkitIcon.AnimatedVector(DesignSystemR.drawable.anim_share)) { context ->
            context.shareApp(shareMessageFormat = AboutR.string.summary_share_message)
        }
    }
    overflow { supportUs() }
    deepLinks { action(ACTION_OPEN_SETTINGS) { SettingsRoute } }
}
```

### 3. Host it

`ShellHost` replaces the app's main screen composable. Keep the theme, the splash screen and the
work that needs the activity (consent, review, update) in the activity.

```kotlin
setContent {
    AppTheme {
        ShellHost(
            graph = graph,
            resolveStart = { startKeyFor(dataStore.getStartupPage(default = HomeRoute.ROUTE_ID).first()) },
            onReady = { keepSplashVisible = false },
        )
    }
}
```

Declare the activity `launchMode="singleTop"` (or keep `singleTask`) so intents that arrive while it
runs reach the shell.

### 4. Pad lists by the shell's bars

Tabs are drawn behind the navigation bar, banner and player so lists scroll under them. Add
`contentPadding()` to a scrolling list's content padding, or pad a screen that does not scroll by
`LocalContentPadding.current`.

```kotlin
LazyColumn(contentPadding = contentPadding(PaddingValues(bottom = 16.dp))) { ... }
```

### 5. Navigate by key

Replace `NavigationManager`-style request channels, `Context.openActivity` for Toolkit screens, and
back-stack helpers with the navigator:

```kotlin
val navigator = LocalShellNavigator.current
navigator.navigate(LicensesRoute)
navigator.goBack()
```

## Removed APIs and their replacements

| Removed | Replacement |
|---|---|
| `StableNavKey`, `NavigationDestination`, `NavigationDestinationType` | `@Serializable` `NavKey`; `tab`, `child` or `page` in the graph |
| `NavigationBackStackActions` (`navigateTopLevel`, `navigateSingleTop`, ...) | `ShellNavigator` (`navigate`, `close`, `goBack`, `selectTab`) |
| `ActivityEntryAnimation`, `BottomNavTransitions`, core:ui `NavigationAnimations` | `ScreenTransition`, `ShellTransitions`, `CrossActivityBackMotion` |
| core:ui `NavigationState`, `rememberNavigationState`, `Navigator` | `ShellNavigator`, `rememberShellNavigator` (created by `ShellHost`) |
| core:ui `NavigationEntryBuilder`, `entryProviderFor` | `tab`, `child`, `page` and `pageIfAbsent` on `ShellGraphBuilder` |
| `appToolkitNavigationEntryBuilders` | `toolkitGraph { }` or `ShellGraphBuilder.toolkitPages()` |
| `BottomBarItem`, `MainNavigationItem` | `tab(key, label, icon, selectedIcon, ...)` |
| `NavigationDrawerItem`, `NavigationRepository`, `DefaultNavigationRepository` | `drawer { settings(); link(...); action(...); spacer() }` |
| `NavigationDrawerRoutes` and its string routes | Keys: `SettingsRoute`, `HelpRoute`, `SupportRoute`; drawer `action` entries for Share and Updates |
| `BottomNavigationBar`, `LeftNavigationRail`, `NavigationDrawerSheet`, `NavigationDrawerItemContent`, `HideOnScrollBottomBar`, `NavigationIcon` | The chrome of `ShellHost` |
| `NavigationDrawerHeader`, `NavigationDrawerBranding` | `appTitle` and `appIcon` of the graph |
| `handleNavigationItemClick` | `link` and `action` entries in the graph |
| `startupDestinationFlow` | `startupValueFlow` from `:library:core:datastore`, mapped to a key in `ShellHost(resolveStart = ...)` |
| Support action of `MainTopAppBar` on the main screen | `overflow { supportUs() }` |
| An intent action checked in `onCreate` and `onNewIntent` | `deepLinks { action(...) { key } }` |

`MainTopAppBar` and `SearchTopAppBar` remain in `:library:core:ui` for screens that draw their own
bar; the shell's pages use `PageScaffold` and `ShellTopAppBar`.

## Toolkit screens

`toolkitGraph { }` registers a page for `SettingsRoute`, `GeneralSettingsRoute`, `HelpRoute`,
`SupportRoute`, `AdsSettingsRoute`, `PermissionsRoute`, `LicensesRoute`, `LibraryExtrasRoute` and
`DeveloperOptionsRoute`. To replace one, register the same key in your builder; the Toolkit's page is
then skipped. Offer the pages where you want them: `settings()` in the drawer, `supportUs()` in the
overflow menu, `link(HelpRoute, ...)`, or `navigate(key)` from a button.

The Toolkit's activities (`SettingsActivity`, `FaqActivity`, `SupportActivity` and the others) and
`StartupActivity` for the first launch still exist in 3.0.0 and are removed as each feature moves to
its page.

## Developer options

`DeveloperOptionsRoute` opens the shell's developer options: navigation layout, app bar and bottom
bar style, transitions, animation speed, the start page and a live view of every back stack. Link to
it in debug builds only:

```kotlin
drawer {
    if (BuildConfig.DEBUG) link(DeveloperOptionsRoute, DeveloperR.string.shell_developer_options, ToolkitIcon.Vector(Icons.Outlined.DeveloperMode))
}
```

## Checklist

- Every key is `@Serializable` and registered in the graph; building the graph fails for a
  tab or start that is not registered, and `keyFor` drops deep links to unregistered keys.
- The activity hosts `ShellHost` inside `AppTheme`, with edge-to-edge enabled.
- Lists pad by `contentPadding()`.
- Nothing imports `navigation.models`, `navigation.ui`, `navigation.backstack`,
  `navigation.animations`, `navigation.data` or `core.ui.navigation`.
